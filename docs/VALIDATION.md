Known limits: Vue adapter targets Vue 2; assets must be served from the app's own origin (the directory is configurable); edits to camera/effects happen before recording; background segmentation edges are imperfect; decoding a photo under 50 megapixels can have transient memory cost; no automatic captions; host server needed for any submission; no durable offline draft storage.

Dependency review: production dependency audit reports zero known vulnerabilities at handoff. The optional Vue 2.7.16 demo dependency is end-of-life and reports one low-severity HTML-parser ReDoS advisory (GHSA-5j4c-8p2g-v4jx). The demo compiles only its trusted checked-in template, not user templates. LT should use its maintained UI framework for new production integrations; upgrading to Vue 3 is not a drop-in change to this legacy adapter. No broad dependency upgrades were applied to ADAPT. MediaPipe Tasks Vision is pinned to 0.10.35, not 1.x (2026-10-24): 1.1.1 keeps the APIs the recorder uses, but it also adds usage logging that POSTs to `https://odml.pa.googleapis.com/v1/log` with a key from its WASM. A sandboxed Chromium run of this recorder with 1.1.1 attempted that request when the segmenter closed; 0.10.32 and 0.10.35 made no requests outside the page's origin. MediaPipe's 1.x README says the metrics cover performance and usage, not camera frames, but sending them would break this repo's no-telemetry statement in `SECURITY.md`. Decided 2026-10-25: no telemetry, so the recorder stays on 0.10.x ([ADR 0001](adr/0001-no-telemetry.md)).
