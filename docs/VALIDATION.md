Extracted from the focused Discuss-It work on ADAPT at `77a82e6ec`, not from ADAPT's whole source/history. ADAPT versions (2026-10-24): every ADAPT result below comes from that baseline or the Discuss-It fork built on it, a non-public line from before ADAPT moved to Laravel 12, with PHP 7.4, Laravel 7.30.4, Vue 2.6.12 and Laravel Mix 6. LT's `master` is now on PHP 8.4 and Laravel 12 (`98f910391`, 2026-10-23) and builds with `laravel-mix ^4.1.4`; this repo has not repeated those checks there, and the recorder has not yet been compiled with Mix 4 (webpack 4). `integrations/adapt/feature.patch` is archived and does not apply to `master`; the supported path is adding only the recorder (see [ADAPT integration](../integrations/adapt/README.md)). Since v0.1.1, CI runs the recorder tests on every pull request (see the README); the dated results below were manual runs.

Automated coverage includes all four backgrounds, audio-only, encoded playback and cleanup; WebKit synthetic capture; mirrored pixels in the saved clip, in WebKit and in Chromium, whose fake camera plays a generated red/blue Y4M frame; native JPEG/PNG/WebP resizing and macOS HEIC decoding; missing MIME, corrupt/oversized/empty photos; cancellation and object-URL release; playback/model failure recovery retaining camera permission; custom photo selection and saved pixels. It also covers takes cancelled or disposed while recording, `stop()` without a take, a failed recorder start, a worker failure during a take (including a preview frame request that fails after Start, and frames drawn while the take stops), a camera or microphone track that ends during a take with and without recorded data, a page hidden during a take, photos over 50 megapixels rejected before decoding, browser errors without a message, a missing microphone with a camera selected, the adapter's `recording` event, and runtime assets, including the worker from source, served from a non-default or cache-busted directory, with no request to any other origin. Tests contain no live ADAPT authentication or writes and never open a real camera or microphone.

The ADAPT deployment separately passed private upload, conversion, posting, signed playback, range requests and authorization tests. Those operations are not part of the standalone demo. The optional integration includes isolated SQLite backend/media tests for LT to adapt to their application, plus a browser check of the patched viewer (`tests/viewer.mjs`, archived with the patch on 2026-10-25: it targets the patched viewer, so it fails against current upstream ADAPT, as expected, and it is no longer a validation step); it excludes dev-site login and live-data smoke scripts. The deployment results above predate the 2026-10-09 review fixes to the patch (comment listing queries, repeat finalize, finalize after a slow upload, the duration limit, processing-failure classification and logging, keeping processed media ready when the upload cannot be removed, prompt sanitizing, and upload recovery, cancellation and progress).

Playwright update (2026-10-24): with Playwright 1.64.1 (Chrome Headless Shell 156, WebKit build 2370), `npm run build` and `npm run test:all` passed all 11 variants on macOS.

Chromium mirror check (2026-10-24): the encoded-pixel mirror check, previously WebKit-only, now also runs in the four Chromium recorder variants (`recorder`, `iphone`, `worker-failure`, `enumeration-failure`). Chromium's fake camera plays a one-frame red-left, blue-right Y4M file that the test writes to a temporary directory. The check was confirmed to fail when the take is not mirrored and when Chromium falls back to its default fake camera. On macOS the four variants passed five rounds in a row (20 checks), and `npm run test:all` passed all 11 variants.

Track-end salvage (2026-10-25): when a camera or microphone track ends during a take, the take stops and the clip so far goes to review with "Your camera or microphone stopped. Review what was recorded, or record again." When nothing was recorded, the take's promise rejects with "Camera or microphone disconnected. Please prepare a new recording." and the recorder returns to `idle` without review. A page hidden during a take keeps its own message and review. The recorder test covers track end with data, track end with no data (recorded chunks dropped) and a hidden page in all five recorder variants. In the four Chromium variants it also covers an audio-only take whose microphone ends, which MediaRecorder stops by itself. The adapter test checks the review message and the no-data path in the UI. The track-end checks were confirmed to fail on the previous code; the hidden-page check guards behaviour that did not change. A lost device is simulated by stopping the track and dispatching `ended`; a real Bluetooth or USB disconnect was not tested. In Playwright's WebKit, a take stopped within moments of starting sometimes never finished: MediaRecorder reported neither `stop` nor `error`, and the adapter stayed on "Finishing your recording…" with Cancel available. The tests therefore wait 1.2 s before ending the track. On macOS, `npm run build` and `npm run test:all` passed all 11 variants, the adapter test passed 30 runs in a row, and the WebKit recorder variant 10. `tests/viewer.mjs` is archived with `feature.patch`; the dated viewer results above describe the patch's baseline only.

No-telemetry checks (2026-10-25), for [ADR 0001](adr/0001-no-telemetry.md): `npm test` now starts with `tests/discuss-it/no-telemetry.mjs`, which checks that `package.json`, the lock file and the staged assets all carry the same exact 0.10.x release. It also scans the staged assets and `resources/js` for any Google API host except the protobuf prefix `type.googleapis.com`, for the `x-goog-api-key` header, and for known analytics and logging endpoints. All five recorder variants now abort and fail on any request outside the test page's origin. With MediaPipe 1.1.1's bundles and WASM staged in place of 0.10.35's, the scan failed on `odml.pa.googleapis.com` and `x-goog-api-key` in both bundles, and a `^1.1.1` pin failed the pin check. The `iphone` and `worker-failure` variants, which segment on the main thread, failed on 1.1.1's POSTs to `https://odml.pa.googleapis.com/v1/log` when the segmenter closed. The worker variants passed, because the recorder ends its worker without closing the segmenter, and 1.1.1 otherwise sends only once a minute. A probe confirmed that the test's request check sees `fetch` and XHR requests from a dedicated worker in both Chromium and WebKit. With 0.10.35, `npm run build` and `npm run test:all` passed all 12 variants on macOS.

Known limits: Vue adapter targets Vue 2; assets must be served from the app's own origin (the directory is configurable); edits to camera/effects happen before recording; background segmentation edges are imperfect; decoding a photo under 50 megapixels can have transient memory cost; no automatic captions; host server needed for any submission; no durable offline draft storage.

Dependency review: production dependency audit reports zero known vulnerabilities at handoff. The optional Vue 2.7.16 demo dependency is end-of-life and reports one low-severity HTML-parser ReDoS advisory (GHSA-5j4c-8p2g-v4jx). The demo compiles only its trusted checked-in template, not user templates. LT should use its maintained UI framework for new production integrations; upgrading to Vue 3 is not a drop-in change to this legacy adapter. No broad dependency upgrades were applied to ADAPT. MediaPipe Tasks Vision is pinned to 0.10.35, not 1.x (2026-10-24): 1.1.1 keeps the APIs the recorder uses, but it also adds usage logging that POSTs to `https://odml.pa.googleapis.com/v1/log` with a key from its WASM. A sandboxed Chromium run of this recorder with 1.1.1 attempted that request when the segmenter closed; 0.10.32 and 0.10.35 made no requests outside the page's origin. MediaPipe's 1.x README says the metrics cover performance and usage, not camera frames, but sending them would break this repo's no-telemetry statement in `SECURITY.md`. Decided 2026-10-25: no telemetry, so the recorder stays on 0.10.x ([ADR 0001](adr/0001-no-telemetry.md)).
