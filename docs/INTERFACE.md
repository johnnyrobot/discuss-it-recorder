# Recorder interface

`new Recorder(canvas, onState?, onError?, options?)` owns its media resources. One instance represents one recorder session. It attaches a hidden muted inline video element; only the composed canvas is shown to the user. `options.assetBase` (default `/assets/discuss-it/`) is the directory that holds the runtime assets. `null` or an empty string also means the default. A query string or fragment is ignored, because MediaPipe adds file names to the directory. Keep it on the app's own origin: browsers start workers only from the page's origin.

`await prepare(settings)` returns discovered video devices when available. Settings: `audioOnly` (false), `facingMode` (`user` or `environment`), optional `deviceId`, `mirror` (false), `background` (`none`, `blur`, `color`, `image`) and `image` (File/Blob for image mode). Call from a user action; render the preview before enabling Record. Browser support requires HTTPS/localhost, getUserMedia, MediaRecorder and canvas capture. Embedded hosts must grant camera/microphone permission to the frame.

`start()` returns a promise resolving to `{blob, mimeType, extension, durationMs}`. `stop()` returns that same promise; if no take has started since the last `prepare()`, it returns a promise rejected with an `InvalidStateError`. Preserve the actual MIME/extension: MP4/M4A when supported, otherwise WebM. `dispose()` is idempotent and must run on unmount/navigation. Disposing during a take discards it: the take's promise rejects with an `AbortError`. Completed clips are in memory; download or submit before unloading. Disposing does not save/upload a clip.

States: `idle → preparing → preview → recording → finalizing → review`; a failed preview/effect may enter `setup-error` while retaining authorized capture. `dispose()` moves any state to `disposed`, which is final: `prepare()` then throws, so create a new `Recorder` for another session. Cancel/dispose and review release tracks. Changing only mirror/background reuses the live camera. Switching devices may reacquire capture and legitimately request permission. No silent raw-camera fallback is used when effects fail. Show setup errors and an explicit Retry/None choice; do not retry automatically in a loop. A take also stops on its own after five minutes, or once it passes 75 MB; the data still to come when it stops can take the file a little over. If the page is hidden (for example the app goes into the background) or background processing stops responding during a take, the take stops, `onError` explains why, and the clip so far goes to review. If a camera or microphone track ends during a take (for example a Bluetooth microphone disconnects), the take stops too. When anything was recorded, `onError` reports "Your camera or microphone stopped. Review what was recorded, or record again." and the clip so far goes to review, where the student can keep it or record again. When nothing was recorded, `onError` reports "Camera or microphone disconnected. Please prepare a new recording.", the take's promise rejects with that error, and the state goes to `idle` with no review. A track that ends outside a take, for example during the preview, reports the same prepare-again message and also returns to `idle`. Outside a take the effect restarts on the main thread, and `start()` throws until it is ready. Once a take is stopping, later errors do not reach `onError`; the take's promise reports the outcome. If MediaRecorder has not finished 3 seconds after the take was told to stop (in WebKit, a take stopped moments after it starts can leave MediaRecorder silent), the take is given up and nothing it recorded is kept. Its promise rejects with "Recording could not be finished. Please record again.", or with the prepare-again message above when a track ended. `onError` reports the same error, the state goes to `idle` with no review, and every camera and microphone track is released. This is reported even when an earlier error stopped the take, because that error promised a review that will not come. A take disposed of meanwhile rejects with an `AbortError` and reports nothing.

Vue 2 adapter: optional Boolean prop `audioOnly` and String prop `assetBase`. `busy` emits a Boolean; while true, the host should block response-type changes/submission. `recording` emits `true` when a take starts and `false` when it ends; time a take from it, not from `busy`, which also covers the preview. `recorded` emits the result, or null when a recorded take is cleared (Retake, Cancel or unmount). Cancel without a take emits nothing, so an attachment the host got elsewhere is kept. A selected camera that has disappeared is deselected, so a retry uses the default camera. A camera the browser still lists stays selected, for example when only the microphone is missing. The adapter handles local review, cancellation and download. Its `beforeDestroy` hook releases resources; a Vue 3 adapter must use the equivalent unmount hook.

MediaPipe model, module, worker and WASM are fetched from `assetBase` on the app's own origin; the worker loads them relative to its own URL. Camera pixels and the selected photo are never sent for remote inference. iPhone/iPad use the DOM-canvas processing path; other browsers use a worker with fallback. Photos over 50 megapixels are rejected from their dimensions before decoding; decoding a smaller photo still briefly uses memory before resizing. Sustained performance, thermal behavior and interruptions vary by hardware. Mirror applies to the complete saved image, including text in a background.

Host responsibilities: sanitize displayed discussion content, authorize every operation, require explicit submission, validate size/duration/codecs server-side, normalize playback media if needed, protect stored media and expiring playback links, provide captions/text alternatives, and define retention/grade policies. This module does not provide automatic transcription or these server controls.

Mobile host layout: include `width=device-width, initial-scale=1`; give the recorder a full-width phone column, use `min-width:0` for flex/fieldset ancestors, and avoid stacking multiple padded containers around it. Keep mobile form controls at least 16px and touch controls at least 44px. Do not disable user zoom. The archived ADAPT patch includes a Discuss-It-specific assessment layout correction.
